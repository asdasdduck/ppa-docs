Animation Action Tags

Choose who targets whom at each stage. Use the in-game editor for a quick fix, or JSON to share changes across animations.

Overview

Without an explicit target, PPA checks nearby openings using reach, approach angles, and the animated shaft’s position and aim. SexLab tags or OStim actions provide scene context that helps it choose. JSON action tags let you choose the target yourself.

Animation action tags are JSON entries keyed by animation ID. Each stage can set an action for actor positions 1 through 5, and can optionally specify which other actor receives that action.

SKSE plugins can also set a live target without changing these files.

Important

The action assigned to an actor position defines where that actor's genitals go. It does not describe what happens to that actor. If actor position 2 has action V, actor 2 is the performer whose penis targets a vagina.

When To Use Action Tags

  • The mod targets the wrong hole, such as vaginal when the stage should be anal.
  • An actor's genitals clip through air or the wrong body part.
  • You want to disable genital tracking for a specific actor in a scene.
  • Automatic detection is unreliable for a specific animation or stage.

Target Values

ValueTargetBehavior
VVaginaPush this actor's genitals toward a vagina target.
AAnusPush this actor's genitals toward an anus target.
MMouthPush this actor's genitals toward a mouth target.
HHandUse hand tracking and choose the closest detected hand.
LHLeft HandUse hand tracking with the left hand.
RHRight HandUse hand tracking with the right hand.
!NoneDisable tracking for this actor position in this stage.
omittedAutoOmit the key for automatic selection unless another file defines it. An empty string "" explicitly restores Auto.
Auto Values

Use "" for Auto when overriding an existing entry. Omitting a key does not erase a target supplied by another file. Unknown strings such as "b" become None.

Actor Positions

Actor positions 1 through 5 correspond to the order reported by the animation framework, such as SexLab or OStim. Position 1 is usually the main actor, position 2 is usually the first partner, and higher positions are additional participants.

The in-game target menu shows the current actor, stage, and target, so it is usually the safest way to identify positions before writing JSON by hand.

Explicit Target Actors

A stage entry can use an object instead of a target string when a scene has multiple possible recipients. The actor-position key still identifies the performer; the object's target field identifies the actor who receives the action.

Actor 2 performs a vaginal action on actor 1
{
  "AnimationName": [
    {
      "s": 1,
      "2": {
        "target": 1,
        "action": "V"
      }
    }
  ]
}
FieldTypeMeaning
targetintegerThe receiving actor position, from 1 through 5.
actionstringOne of the target values listed above: V, A, M, H, LH, RH, or !.

The compact string form, such as "2": "V", leaves the recipient unspecified. Use the object form when the performer must interact with one specific actor.

Self Interaction

A performer may target their own actor position only for H, LH, or RH. This explicitly configures masturbation with that actor's own hand. Self-targeted vagina, anus, and mouth actions are not supported.

JSON Files

Animation tags are loaded from:

Data/SKSE/Plugins/ppa-animation-tagging/

The loader reads every .json file in that folder. Entries merge by stage and performer, so a small override can change one interaction without replacing the rest of the animation.

File Priority

Files are sorted in reverse alphabetical order. Later-loaded files have higher priority, so names that sort earlier alphabetically win over names that sort later.

FilePriorityNotes
z_something.jsonLowestLoaded first.
a_something.jsonHigherLoaded after z_ files.
0_your_custom_tags.jsonHigherUsed by the in-game save menu; wins over files named a_ or z_.

Put personal overrides in 0_your_custom_tags.json when you want them to beat bundled defaults. If you want your hand-edited file separate from the in-game editor's output, use a filename that still sorts before the bundled defaults.

Basic Format

Stage array format

Use this compact format when you only need stage targets and do not need the manual flag.

{
  "AnimationName": [
    {
      "s": 1,
      "1": "V",
      "2": "!"
    },
    {
      "s": 2,
      "1": "V",
      "2": "!"
    },
    {
      "s": 3,
      "1": "A",
      "2": "!"
    }
  ],
  "AnotherAnimation": [
    {
      "s": 1,
      "2": "M"
    }
  ]
}
FieldTypeMeaning
AnimationNamestringThe exact animation ID reported by the framework.
sintegerThe stage number.
1 through 5string or objectThe performer position's action, optionally paired with a specific target actor.

Extended Format With Manual Flag

Manual animation format

The manual flag disables automatic selection outside the stored stage range. Use explicit "!" entries to disable performers within a stage.

{
  "AnimationName": {
    "manual": true,
    "stg": [
      {
        "s": 1,
        "1": "V",
        "2": "!"
      },
      {
        "s": 2,
        "1": "A",
        "2": "!"
      }
    ]
  }
}

In the current loader, manual = true makes stages outside the stored range resolve to None. Omitted performer positions inside that range still use Auto. Write "!" for every position you want disabled, and list each stage you want to control.

Method 1: In-Game Editing

Look at an actor in an active scene to use the target menu. These steps describe the custom target window; UseSkyrimUI = true uses fallback panels.

1

Start the animation scene.

2

Look at a scene actor and press Select Actor. The shipped binding is Backspace (SelectActor = 14); older configs may differ.

3

Choose the Performer, or click the highlighted shaft on screen.

4

Choose a Target Actor. Leave it on Automatic to use the compact action format, or select a specific actor to save an explicit pairing.

5

Select the stage or stage range to update.

6

Select Vagina, Anus, Mouth, Hand, Left Hand, Right Hand, None, or Auto Detect. You can also click a highlighted on-screen orifice or hand to choose its actor and action together.

7

Repeat for other performers, targets, and stages as needed.

8

Select Save Changes to write changes to 0_your_custom_tags.json.

Testing

Target edits update active scenes immediately. Use this window’s Save Changes button before reloading; reload clears unsaved target edits. The settings menu’s auto-save does not save animation tags.

Method 2: Manual JSON Editing

Manual editing is useful for bulk changes or for animations you cannot test in-game.

Step 1: Find The Animation Name

Open the target window during the animation and copy its displayed animation ID. You can also find the ID with your animation framework’s tools.

Step 2: Create Or Edit Your Custom File

Open or create:

Data/SKSE/Plugins/ppa-animation-tagging/0_your_custom_tags.json

Step 3: Add Animation Entries

{
  "SexLabAnimation_Missionary_A1": [
    {
      "s": 1,
      "1": "!",
      "2": "V"
    },
    {
      "s": 2,
      "1": "!",
      "2": "V"
    }
  ]
}

This example disables actor position 1 and makes actor position 2 target a vagina in stages 1 and 2. Add more stage objects as needed. OStim uses its scene ID and stage 1.

Step 4: Reload and Check

Save pending in-game target edits first, then use Reload (F5 by default) to load your JSON. The load runs in the background. If the current scene still shows an old target, restart that scene after loading finishes; active scenes cache their tag data.

Troubleshooting

  • A tagged hole never activates: explicit tags bypass automatic aim limits, but still need to pass reach and approach checks. Check the entrance path too.
  • Nothing changes: confirm the animation ID exactly matches the framework ID and that the JSON file is inside ppa-animation-tagging.
  • Your file loses priority: rename it so it sorts before the files you want to override, or use 0_your_custom_tags.json.
  • Auto behaves like disabled after manual edits: use an empty string "" instead of an unknown value.
  • A disabled performer still tracks: put "!" on that performer in each relevant stage. The manual flag alone does not disable omitted positions inside the stored stage range.
  • An explicit pairing is ignored: confirm both target and action are present, the target is an integer from 1 through 5, and the action is a string.
  • Invalid JSON: one syntax error can prevent the whole file from loading. Check commas, quotes, and matching braces.
